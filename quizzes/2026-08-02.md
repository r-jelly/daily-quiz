## Q1. Function Calling과 단순 프롬프팅의 차이

LLM이 "이 질문에는 계산기 tool을 써야겠다"처럼 스스로 tool 호출 여부와 어떤 tool을 쓸지 판단하는 과정은, 그냥 프롬프트에 "필요하면 계산기를 써"라고 지시문을 넣는 것과 근본적으로 뭐가 다를까요? 모델이 tool use를 "하도록 만드는" 메커니즘이 무엇인지, 그리고 왜 이게 단순 프롬프팅만으로는 안정적으로 되지 않는지 설명해보세요.

### Answer 1.

tool의 input/output/description을 prompt에 제공하면, LLM이 해당 tool의 이용 정보를 JSON과 같은 형태로 출력해 이를 Python 등이 파싱해서 실행하는 flow로 tool use가 이루어진다. 단순 프롬프팅 "필요하면 계산기를 써"와는 다르게 직접적인 사용 방법, 입력값, 출력값을 보고 모델이 선택하게 되므로 더 잘 사용하게 할 수 있다.

> **📝 보완·모범답안:**
> - **정확한 핵심:** tool schema(이름, description, input/output 스펙)를 prompt에 주입하고 모델이 JSON 등 구조화된 형태로 tool call을 출력, 이를 파서가 실행하는 flow 자체는 정확하다. 하지만 이것이 "더 잘 되는" 진짜 이유는 두 층위로 나뉜다: (1) 모델이 이 tool-call 포맷을 SFT 단계에서 명시적으로 학습했다는 점, (2) 프로덕션 시스템은 여기에 더해 constrained/grammar decoding(JSON mode 등)으로 출력 자체를 스키마에 맞게 강제한다는 점.
> - **기존 답변에서 빠졌거나 틀린 점:** "왜 단순 프롬프팅은 불안정한가"에 대한 구조적 이유가 빠졌다. 자유 텍스트 생성은 출력 형식에 제약이 없어 파싱이 깨지기 쉽고, 존재하지 않는 tool 이름·파라미터를 hallucinate할 위험이 크다. function calling은 "모델이 알아서 잘 따라주길 바라는" 것이 아니라 포맷을 구조적으로 학습/강제한다는 차이가 핵심.
> - **한 단계 더:** OpenAI/Anthropic의 function calling API가 내부적으로 JSON schema validation과 constrained decoding을 결합하는 방식, 그리고 Toolformer(Schick et al., 2023)처럼 모델이 self-supervised로 "언제 tool을 호출할지"를 학습하는 접근까지 연결해서 이해하면 좋다.

## Q2. ReAct의 Reasoning-Action 인터리빙이 해결하는 문제

ReAct(Reasoning + Acting) 방식은 tool call을 한 번에 몰아서 하지 않고, Thought → Action → Observation을 반복하는 루프로 만듭니다. tool 목록을 주고 한 번에 답을 생성시키는 것과 비교했을 때, 이렇게 reasoning과 action을 번갈아 인터리빙하는 구조가 실제로 어떤 문제를 해결해주나요?

### Answer 2.

큰 문제를 작은 부분부터 해결하게 함으로써 복잡한 문제도 여러 단계를 거쳐서 풀 수 있다. 또한 이전 action의 context를 다음 thought가 참조하게 함으로써 문제를 step-by-step으로 풀 수 있는 지식을 주입하게 된다.

> **📝 보완·모범답안:**
> - **정확한 핵심:** step-by-step 분해와 이전 결과 참조라는 방향은 맞지만, 이는 순수 Chain-of-Thought도 어느 정도 제공하는 이점이라 ReAct만의 차별점을 더 짚어야 한다. ReAct 고유의 가치는 두 가지: (1) Grounding — Observation이 모델의 상상이 아니라 실제 tool 실행 결과이므로 다음 Thought가 외부 세계의 실제 정보에 근거하게 되어 hallucination이 줄어든다. (2) Closed-loop 제어 — 한 번에 계획을 다 세워 실행하는 open-loop 방식과 달리, 매 스텝 Observation을 보고 다음 Action을 결정하므로 중간에 계획을 수정(예: 검색 쿼리 재구성)할 수 있다.
> - **기존 답변에서 빠졌거나 틀린 점:** "실제 관측을 통한 hallucination 억제"와 "closed-loop 적응"이라는 ReAct 고유의 차별점이 명시되지 않았다.
> - **한 단계 더:** ReAct 원 논문(Yao et al., 2022)의 실험에서 reasoning-only(CoT)와 acting-only 대비 ReAct가 factual grounding과 error recovery 양쪽에서 우위를 보인 부분, 그리고 이후 Reflexion·agentic RAG로 이어지는 계보를 함께 봐두면 좋다.

## Q3. Reflexion — 실패 경험의 재활용

ReAct 루프를 여러 번 돌려도 문제를 못 풀고 계속 실패하는 상황(예: 같은 검색을 반복하거나 잘못된 tool을 계속 호출)에서, 이 반복 실패를 다음 시도(혹은 다음 세션)에 활용해 성능을 개선하려면 어떤 접근이 가능할까요? Reflexion이 이 문제를 어떻게 다루는지 설명해보세요.

### Answer 3.

잘 모르겠습니다. 추측하자면, 실패 원인을 분석해서 이를 다음 context로 반영해 LLM이 self-correction하도록 유도하는 방법을 사용할 수 있을 것 같습니다.

> **📝 보완·모범답안:**
> - **정확한 핵심:** 추측이 정확히 맞다. Reflexion(Shinn et al., 2023)은 Actor–Evaluator–Self-Reflection 세 요소로 구성된다. Actor(ReAct 스타일 LLM)가 시도를 하면 Evaluator가 성공/실패를 스코어링하고, Self-Reflection 모델이 "왜 실패했는지, 다음엔 뭘 다르게 할지"를 자연어 문장으로 생성한다. 이 reflection은 weight update 없이 memory buffer에 텍스트로 저장되어 다음 시도의 context에 주입된다.
> - **기존 답변에서 빠졌거나 틀린 점:** 몰랐다고 인정했지만 방향은 정확했다. 구체적으로 빠진 것은 (1) Actor/Evaluator/Self-Reflection이라는 3분할 구조, (2) gradient update 없이 자연어 텍스트만으로 개선한다는 "verbal reinforcement learning" 개념.
> - **한 단계 더:** 이는 policy gradient(RL)가 파라미터에 반영하는 일을, 자연어 self-critique를 context에 축적하는 것으로 대체한 접근이라는 점에서 RLHF/PPO 계열과 대조해서 이해하면 좋다. 관련 확장으로 memory 축적 방식이 다른 agentic 메모리 연구(예: Generative Agents, MemGPT)도 함께 봐두면 좋다.

## 오늘의 수식 카드

**1. ReAct의 policy 조건화**

$$a_t \sim \pi_\theta(a_t \mid c_t), \qquad c_t = (o_1, a_1, \dots, o_{t-1}, a_{t-1})$$

$a_t$는 시점 $t$의 action(tool call 포함), $o_t$는 그 결과 observation, $c_t$는 이전까지의 (Thought, Action, Observation) 궤적을 누적한 context. 매 스텝 $o_{t-1}$이 $c_t$에 포함되어 policy가 실제 관측에 조건화된다는 점이 open-loop 계획과의 핵심 차이.

**2. Reflexion의 verbal reinforcement**

$$sr_t = M_{\text{reflect}}(\tau_t, r_t), \qquad \pi_\theta\big(a \mid c,\ \text{mem} \cup \{sr_1, \dots, sr_{t-1}\}\big)$$

$\tau_t$는 $t$번째 시도의 전체 궤적, $r_t$는 evaluator가 매긴 성공/실패 신호, $sr_t$는 이를 바탕으로 생성된 자연어 self-reflection. gradient update 없이 $sr_t$를 memory buffer에 누적해 다음 시도의 context에 주입하는 것이 핵심.
