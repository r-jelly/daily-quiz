## Q1. KV Cache와 반복 계산 제거

Transformer 디코더에서 자기회귀(autoregressive) 생성 시, 매 스텝마다 이전 토큰들의 Key/Value를 재계산합니다.

**두 가지를 설명하세요:**

1. **KV Cache의 원리** — 왜 반복 계산이 발생하는지, KV Cache가 이를 어떻게 제거하는지 설명하세요.

2. **시간 복잡도 변화** — KV Cache 없이 길이 $T$의 시퀀스를 생성할 때와, KV Cache를 사용할 때의 계산 복잡도를 비교하세요.

### Answer 1.

1. Autoregressive 생성에서 현재 시점 t에서의 토큰을 생성할 때, Attention 연산을 위해서는 이전 t-1까지의 토큰에 대한 Key, Value를 계속 계산해야 한다. KV cache는 계산한 Key, Value를 캐싱해두고 새로 들어온 토큰의 K, V만 재계산 함으로써 이러한 중복 연산을 제거할 수 있게 된다.

$$\text{Attention}(Q_t, K_{1:t}, V_{1:t}) = \text{softmax}\!\left(\frac{Q_t K_{1:t}^\top}{\sqrt{d_k}}\right) V_{1:t}$$

2. 만약 cache가 없다면, 이전 t-1개 토큰의 Key, Value를 매번 전부 계산해야 한다. 따라서 각 step당 $O(t^2)$의 시간복잡도를 갖고, 전체 T개 토큰 생성시 $O(T^3)$의 시간복잡도를 갖게된다.

반면, KV cache를 사용한다면, 새 토큰의 Q, K, V만 계산하고 이전 토큰의 K, V는 캐시에서 조회하기 때문에, step당 새 Query와 캐시된 t개의 K를 내적하기 위한 $O(t)$의
시간복잡도가 생기고, 전체 T개 토큰 생성시 $O(T^2)$의 시간복잡도를 갖게된다.

$$\text{Without cache: } O(T^2 \cdot d), \quad \text{With cache: } O(T \cdot d)$$

## Q2. KV Cache 메모리 수식과 MQA/GQA

KV Cache는 메모리를 많이 사용합니다.

**두 가지를 답하세요:**

1. **KV Cache 메모리 수식** — 레이어 수 $L$, 헤드 수 $H$, 시퀀스 길이 $T$, 헤드 차원 $d_k$, 배치 크기 $B$를 사용하여 KV Cache의 메모리 크기를 수식으로 표현하세요.

2. **MQA와 GQA** — VRAM 사용량을 줄이기 위한 Multi-Query Attention(MQA)와 Grouped-Query Attention(GQA)이 KV Cache 메모리를 어떻게 줄이는지 설명하세요.

### Answer 2.

1. 전체 KV Cache의 VRAM 사용량은 아래와 같이 계산된다.
$$\text{KV Cache Memory} = 2 \cdot B \cdot L \cdot H \cdot T \cdot d_k \cdot \text{bytes}$$

2. 기존 Transformer의 Multi-Head Attention(MHA)은 각 헤드마다 독립적인 K, V를 갖게 된다. Multi-Query Attention(MQA)은 K, V를 1개만 사용하여 모든 Q에 대해서 같은 K, V 헤드를 사용하도록 한다. Grouped-Query Attention(GQA)은 H개의 Q 헤드를 G개의 그룹으로 묶고, 같은 그룹 내의 Q들이 하나의 K, V 헤드를 공유하게 된다. 따라서, GQA는 MHA보다 VRAM을 적게 사용하고, MHA보다는 표현력이 풍부하다는 장점을 가진다. 실제 LLaMA-3, Mistral 등의 모델이 해당 기법을 채택했다.

$$\text{MHA: } H_Q = H_K = H_V = H$$
$$\text{MQA: } H_K = H_V = 1$$
$$\text{GQA: } H_K = H_V = G, \quad 1 < G < H$$

## Q3. Speculative Decoding

KV Cache 외에 LLM 추론 속도를 높이는 기법으로 Speculative Decoding이 있습니다.

Autoregressive 생성의 어떤 근본적인 병목을 해결하려는 기법인지, 그리고 동작 원리(Draft model + Target model의 역할)를 설명해보세요.

> 힌트: Draft model과 Target model의 출력 분포가 유사할수록 수용률이 높아집니다.

### Answer 3.

Autoregressive 생성 방법의 근본적인 병목은, 이전 토큰이 생성되어야 다음 토큰을 생성할 수 있다는 것이다. Speculative Decoding은 이러한 병목을 해결하기 위한 기법인데, 경량 모델인 Draft model이 빠르게 토큰을 생성하고 대형 모델인 Target model이 이를 한 번의 forward로 검증해 특정 비율로 토큰을 수용해 생성 속도를 빠르게 하는 점이 장점이다.

조금 더 자세히 설명하면 아래와 같다:
1. Draft model (소형): $k$개의 토큰을 Autoregressive하게 생성
2. Target model (대형): $k$개 draft token을 한 번의 forward pass을 통해 병렬적으로 검증
3. 각 토큰을 아래 비율로 수용/거절을 결정

$$\text{speedup} \approx \frac{1 + K\alpha}{1 + K \cdot \frac{T_{\text{draft}}}{T_{\text{target}}}}$$

4. 첫 거절(reject)이 나올 때까지의 모든 토큰은 그대로 사용하고, 거절된 위치부터 Target model의 분포로 샘플링을 진행한다.

따라서, target model의 출력 분포를 보장하면서도 속도를 높일 수 있다. rejection sampling이 있어 원본 모델의 품질 손실이 없다는 점이 장점이다.
