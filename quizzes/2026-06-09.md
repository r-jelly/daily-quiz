## Q1. Flash Attention이 빠른 이유 — 메모리 병목과 Tiling·Recomputation

Flash Attention은 attention 연산을 "더 적게" 계산해서 빨라지는 게 아닙니다. 표준 attention 구현의 진짜 병목이 FLOPs가 아니라 GPU 메모리 계층(HBM ↔ SRAM) 사이의 데이터 이동(memory-bound)이라는 점을 설명하고, 이를 해결하는 두 가지 기법인 Tiling(블록 분할)과 Recomputation을 함께 설명해보세요.

### Answer 1.

표준 attention은 $QK^\top$으로 $n\times n$ 행렬을 만들게 된다. 이때 연산 결과를 저장했다가 softmax를 위해서 읽어오는 과정을 반복하게 된다. 즉, HBM과 SRAM 사이에 메모리 입출력 과정이 병목이 된다. 연산 처리량이 메모리 대역폭보다 보통 빠르므로, attention 연산 결과 행렬은 메모리 대역폭에 묶이게 된다. SRAM은 매우 빠르지만 용량이 작아 행렬 그대로를 사용하기에는 어렵다.

이때 Flash Attention은 전체 $n\times n$ 행렬을 한 번에 만들지 않고, 작은 블록 단위로 쪼개 SRAM에서 연산을 할 수 있게 하는 Tiling 기법을 도입한다.

또한 backpropagation 시에는 attention 행렬이 필요한데, Flash Attention에서는 이를 저장해서 사용하지 않고, 필요할 때마다 다시 계산하는 Recomputation 방식을 사용한다.

> **흔히 놓치는 지점:** "Flash Attention이 attention의 계산 복잡도 $O(N^2)$를 낮춘다"는 오해. FLOPs는 동일하다. 줄어드는 것은 HBM 접근 횟수(IO)다.

## Q2. Online softmax의 블록 단위 rescaling

Flash Attention은 K·V를 블록으로 쪼개 순차 처리하면서도 전체 행을 한 번에 보지 않고 정확한 softmax를 계산합니다. online softmax가 running max와 running sum을 유지하면서, 새 블록이 올 때 이전 누적값을 어떻게 재보정(rescale)하는지 설명해보세요.

### Answer 2.

실제 Softmax 계산은 수치 안정성을 위해서 항상 최댓값을 빼고 계산한다.
$$
\text{softmax}(x_i) = \frac{e^{x_i-m}}{\sum_j e^{x_j-m}},\quad m=\max_k x_k
$$

이때, (j-1)번째 블록까지 계산해둔 값은 해당 시점의 최댓값(running max) $m_{j-1}$을 기준으로 shift되어 있다. (softmax는 전체 행을 봐야 정규화할 수 있음)
새로운 블록의 최댓값 $\tilde{m}_j$가 더 크다면 $m_j = \max(m_{j-1}, \tilde{m}_j) > m_{j-1}$이 된다.
기존에 누적된 running sum $l_{j-1}$은 더 작은 기준점($m_{j-1}$)로 나눠져 있으므로 새로운 블럭 값과 같은 스케일이 아니다.

따라서 기존 누적값에 항상 $e^{m_{j-1}-m_j}$를 곱해서 새로운 기준점으로 맞춘 뒤에 더해주게 된다.(rescaling) 최종적으로 모든 블록 연산이 끝나면 최종적으로 출력값은 $\text{Output}_\text{last} / l_\text{last}$로 정규화해주면 된다.

따라서 전체 행을 한 번에 메모리에 올리지 않고도 수치적으로 안정적인 softmax 결과를 얻게 된다.

## Q3. Backward pass에서의 재계산(recomputation)

Flash Attention은 forward에서 $N\times N$ 점수 행렬 $P$를 저장하지 않고 버립니다. 그렇다면 backward pass에서 gradient를 계산할 때 $P$를 어떻게 다시 만들어내는지, 무엇을 저장해 두었다가 활용하는지 설명해보세요.

### Answer 3.

Flash Attention의 forward에서 $n\times n$의 $P$는 버리지만, 행 단위 통계인 row max와 row sum은 그대로 저장을 한다. 이건 크기가 $O(n)$이라 메모리 부담이 거의 없다.

backward에서는,
1. $Q_i, K_j$ 블록을 SRAM으로 가져와 $S_{ij}=Q_iK_j^\top/\sqrt{d_k}$를 재계산한다.
2. 이미 정확한 $m_i$(row max), $l_i$(row sum)을 알고 있으므로, online softmax의 복잡한 rescaling 없이 곧바로 $P_{ij}=e^{S_{ij}-m_i}/l_i$로 $P$ 블록을 즉시 복원한다.
3. 구한 $P$를 이용해 표준 softmax backward로 gradient를 구한다.

즉, HBM 저장 대신 저렴한 계산으로 바꾸는 방식이 forward, backward 모두 적용된다.

> **한 단계 더:** gradient checkpointing과의 연결, GRPO의 advantage 정규화·RLHF의 reward normalization처럼 running statistics를 재활용하는 유사 패턴을 함께 알아두면 좋다.

## 오늘의 수식 카드

**Online Softmax 재보정 (블록 누적)**

새 블록의 점수 $S^{(j)}$가 올 때, running max $m$과 running sum $\ell$을 갱신:

$$m^{new} = \max(m,\; \max S^{(j)}), \qquad \ell^{new} = e^{m - m^{new}}\ell + \sum e^{S^{(j)} - m^{new}}$$

**IO 복잡도**

$$\text{HBM 접근} = O\!\left(\frac{N^2 d^2}{M}\right)$$

| 기호 | 의미 |
|------|------|
| $N$ | 시퀀스 길이 |
| $d$ | head 차원 |
| $M$ | SRAM 크기 |
| $m, \ell$ | 지금까지 본 블록들의 running max·running sum |

직관: 전체 행을 한 번에 정규화하는 대신, 블록을 볼 때마다 이전 부분합을 지수적으로 다시 스케일해 "정확한" softmax를 온라인으로 누적한다. 큰 중간 행렬을 HBM에 안 쓰는 것이 속도 이득의 원천.
